## 2026-03-26 - Repeated JSON.parse in Render Loops
**Learning:** Found a pattern where structured data (payment terms) is stored in a stringified `notes` column. This leads to `JSON.parse(o.notes)` being called multiple times per row inside rendering and filtering loops (which execute on every keystroke).
**Action:** Always pre-parse JSON strings into object properties immediately after data fetch so that subsequent filters and renders can just access the object properties without expensive recalculations.
## 2025-02-27 - Double loop / JSON parse of orders in Astro components
**Learning:** `src/pages/index.astro` fetched a raw list of orders and mapped over it to execute `JSON.parse` into an `orders` array. Further down in the file, it repeated the `.map` over the `orders` array and executed `JSON.parse` a *second* time on the identical notes property. Attempting to globally parse `notes` string fields in other routes (like `clientes/analisis.astro`) can break financial calculations if the fallback logic `JSON.parse(o.notes || '{}')` is not respected, because calculating properties expecting an empty object will fail if the parent is `undefined`.
**Action:** When reusing properties, verify if the property already exists from an earlier mapped step instead of mapping it twice. Ensure that any default object fallbacks in downstream logic are preserved when converting parsed properties.
